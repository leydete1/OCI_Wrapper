# ======================================================================
# run_plan.txt - HTTP tester run plan (2026-10-14, points d1-d3)
#
# Lives next to Run.sh in Testers/. The tester reads it at startup.
#
#   [solo]            run one at a time, in this order, BEFORE anything
#                     else - they see the database exactly as
#                     Reset_Tester_Objects.sql left it.
#   [chain <name>]    run in this order, one after the other, on one
#                     thread. Chains run alongside each other and
#                     alongside every fixture not listed here.
#
# Every fixture listed here is compared strictly: any difference from
# its baseline is a FAIL. End a line with the word  variance  to keep
# the old tolerant rule for that one fixture.
#
# The XML and JSON versions of each round share their keys (both
# Insert_Round_5 files insert 501 and 502, for example), so each pair
# goes in the same chain. Then the shared keys do no harm and no
# fixture file needs to change.
#
# A name here with no fixture file is a FAIL; a name listed twice stops
# the tester before it starts. '#' starts a comment.
# ======================================================================
